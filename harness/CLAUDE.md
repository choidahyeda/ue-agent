# 하네스 작업 규칙 (AI 에이전트용)

이 폴더는 "게임 개발 자동화 포트폴리오" 작업을 AI 에이전트가 이어서 진행하기 위한 하네스입니다.
세션이 바뀌어도 이 폴더의 문서만 읽으면 지금 어디까지 왔고 다음에 무엇을 할지 알 수 있어야 합니다.

## 세션 시작 시 반드시 읽는 순서

1. `CLAUDE.md` (이 파일)
2. `status/TASKS.md` : 지금 할 일, 확인할 것, 남은 작업
3. `logs/` 에서 가장 최근 날짜 파일 1~2개 : 직전 세션에서 한 일과 막힌 점
4. 작업하려는 태스크와 관련된 `docs/`, `specs/` 문서만 골라서 읽기

읽은 뒤, 작업을 시작하기 전에 사용자에게 한 줄로 알린다.
"오늘은 TASKS.md의 [태스크 ID] 부터 진행합니다."

## 작업 중 규칙

- **한 번에 한 태스크.** TASKS.md에서 `[진행 중]`으로 옮기고 시작한다.
- **규칙 값은 하드코딩 금지.** 해상도, 트라이앵글 예산, 인스트럭션 수 등 모든 기준은 `specs/asset_rules.yaml`에서 읽는다. 기준을 바꿔야 하면 YAML을 고치고 로그에 이유를 남긴다.
- **검사 도구는 Python으로 작성.** (지원 공고 필수요건이 Python/TypeScript)
- **완료 조건을 먼저 확인.** 각 태스크의 "완료 조건"을 만족해야 완료로 표시한다. 실행해서 확인하지 않은 것은 완료가 아니다.
- **언리얼 에디터에서 파괴적 작업 금지.** 에셋 삭제, 이름 변경, 대량 수정은 dry-run 결과를 먼저 보여주고 사용자 승인을 받은 뒤 실행한다.
- **타임박스.** 공식 언리얼 MCP의 Toolset Registry 등록이 2시간 안에 안 되면 우회안(`docs/03_plan_3days.md` 참고)으로 바로 전환하고 `status/DECISIONS.md`에 기록한다.
- **넥슨 자산 사용 금지.** 이전 회사 코드, 사전, 내부 규칙 데이터는 절대 쓰지 않는다. 설계 경험만 이력서와 면접에서 이야기한다.
- **문서 표기 규칙.** 문서를 쓸 때 가운데 점(·)을 쓰지 않는다. 쉼표나 다른 표현으로 대체한다.

## 세션 종료 시 반드시 할 일

1. `status/TASKS.md` 갱신
   - 끝난 태스크는 `[x]` 로 바꾸고 "완료" 섹션으로 이동
   - 새로 발견한 할 일, 확인할 것 추가
2. `logs/YYYY-MM-DD.md` 작성 (오늘 날짜 파일이 있으면 그 아래에 이어서 추가)
   - 형식은 `logs/_TEMPLATE.md` 를 따른다
3. 방향이 바뀌는 결정을 했다면 `status/DECISIONS.md` 에 한 줄 추가
4. 사용자에게 오늘 한 일과 다음 태스크를 3줄 이내로 요약

## 폴더 구조

```
harness/
├─ CLAUDE.md            # 이 파일. 에이전트 작업 규칙
├─ AGENTS.md            # Codex 등 다른 에이전트용 진입점 (CLAUDE.md를 따르라는 안내)
├─ README.md            # 사람이 보는 하네스 소개
├─ status/
│  ├─ TASKS.md          # 해야 할 작업, 확인할 것, 남은 작업, 완료 (현황판)
│  └─ DECISIONS.md      # 주요 결정 기록
├─ logs/
│  ├─ _TEMPLATE.md      # 날짜별 로그 양식
│  └─ YYYY-MM-DD.md     # 날짜별 작업 기록
├─ docs/
│  ├─ 01_goal_and_positioning.md   # 목표, 지원 공고 분석, 어필 포인트
│  ├─ 02_architecture.md           # 전체 구조와 코드 폴더 구성
│  ├─ 03_plan_3days.md             # 3일 실행 계획과 완료 조건
│  ├─ 04_backlog.md                # 제출 후 확장 과제와 우선순위
│  ├─ 05_ue58_mcp_notes.md         # UE 5.8 언리얼 MCP 조사 내용
│  ├─ 06_knowledge.md              # 알아야 할 지식 목록
│  └─ 07_resume_and_interview.md   # 경력 기술 초안, 예상 면접 질문
└─ specs/
   ├─ asset_rules.yaml             # 검사 규칙 (단일 기준 파일)
   └─ test_assets_plan.md          # 테스트 에셋 정답지와 측정 표
```

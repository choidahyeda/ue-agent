## 2일차: 에이전트로 묶기

| ID | 작업 | 완료 조건 |
|---|---|---|
| D2-1 | 커스텀 툴세트 등록 | Claude Code에서 공식 언리얼 MCP를 통해 검사 툴 호출 성공 |
| D2-2 | 프로젝트 CLAUDE.md | 스튜디오 규칙, 금지 행동, 리포트 해석 방법 포함 |
| D2-3 | 서브에이전트 2개 | auditor는 쓰기 권한 없음, fixer는 dry-run 결과만 먼저 제시 |
| D2-4 | 안전 훅 | 삭제, 이름 변경, 대량 수정 시도 시 실행 전에 멈추고 확인 요청 |
| D2-5 | `/audit` 커맨드 | 검사 실행 → error 먼저, 담당 부서별로 묶어서 이유와 수정 방법 설명 |
| D2-6 | (여유 시) UPROPERTY 누락 검사 | 샘플 C++ 파일에서 UObject 원시 포인터 멤버 탐지 |

**D2-1 우회안 (2시간 타임박스 초과 시)**:
에디터 Python 검사를 커맨드라인으로 실행하는 스크립트(`scripts/run_audit.py`)를 만들고,
Claude Code 슬래시 커맨드나 스킬에서 그 스크립트를 호출한다.
공식 MCP는 에디터 조회와 수정 쪽(선택된 에셋 확인, 속성 변경)에만 사용한다.
우회 사실과 이유는 `status/DECISIONS.md` 와 README에 명시한다. (실험 기능 한계를 파악하고 대응한 사례로 활용)

## 데모 시나리오 (D3-4)

1. 아티스트가 4096 해상도 텍스처와 LOD 없는 메시를 Props 폴더에 추가
2. `/submit` 실행 → 두 에셋에서 error 발견, 커밋 차단
3. 에이전트가 "Props 카테고리 최대 1024, 이유는 텍스처 스트리밍 풀 부족" 식으로 설명
4. fixer가 수정안 dry-run 제시 → 승인 → 반영
5. 다시 `/submit` → 통과, 커밋 메시지 초안 확인 후 커밋

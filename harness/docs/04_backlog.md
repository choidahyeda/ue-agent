# 백로그 (제출 이후 확장 과제)

제출 전 필수 범위는 `docs/03_plan_3days.md`. 이 문서는 제출 후 면접 전까지 추가할 과제입니다.
README의 "로드맵" 섹션에도 이 목록을 요약해서 넣습니다.

---

## 우선순위 1: 코드 모듈 확장

언리얼 C++, Blueprint 실무 경험이 가장 잘 드러나는 영역.

- UObject 포인터 UPROPERTY 누락 (GC에 수거되는 버그)
- Tick 안에서 무거운 호출: GetAllActorsOfClass, 문자열 연산, 검색
- 루프 안 Cast 남용, FString과 FName 혼용
- 게임 스레드 밖에서 UObject 접근
- Blueprint: Tick 활성화 목록, Cast 노드로 인한 하드 레퍼런스 체인
- 실행 시점: Claude Code 훅 또는 헤드리스 모드로 커밋, PR 시점 자동 실행

## 우선순위 2: 성능 캡처와 플랫폼 예산

- 레벨 안 카메라 지점 목록 정의
- 각 지점에서 stat unit, stat gpu, 드로우콜, 트라이앵글 수 자동 기록
- 플랫폼별 목표(예: PC 60fps, 콘솔 30fps)와 비교해 초과 지점 표시
- 초과 지점 주변 액터와 머티리얼을 에셋 검사 결과와 엮어 LLM이 원인 후보 요약
- 확장: 스케일러빌리티 단계별 스크린샷 비교, 디바이스 프로파일 설정 비교

## 우선순위 3: 기획 DataTable 검증

- 참조 무결성 (존재하지 않는 ID 참조)
- 값 범위 초과, 밸런스 이상치
- String Table 용어 규칙 검사 (확률 표기 등, 넥슨 경험을 설계로만 활용. 데이터는 새로 작성)

## 우선순위 4: 비개발자용 제출 도우미 확장

- 슬랙에서 "오늘 작업한 거 올려줘" → 각 PC의 로컬 에이전트가 변경 목록 제시
- 작업 중으로 보이는 파일 별도 표시
- 잠긴 파일이나 다른 사람이 작업 중인 에셋이면 알려주고 중단
- README에 Perforce 환경 설계 기술: 체크아웃 잠금, 체인지리스트 단위 제출

## 우선순위 5: 체인지리스트 기반 성능 회귀 추적

- 변경마다 고정 카메라 지점에서 성능 측정해 기록
- 회귀 감지 시 해당 구간 변경을 이분 탐색으로 좁혀 원인 변경 특정
- 원인 변경의 에셋을 에셋 검사에 돌려 근거 수집 (예: 머티리얼 인스트럭션 수 3배 증가)
- LLM 리포트와 담당자 알림
- 버전 관리: Git으로 시작, 가능하면 Perforce 소규모 무료 옵션으로

## 우선순위 낮음: 커뮤니티 여론 리포트

HuggingFace 우대사항 보완용. 메인 킷 시간을 뺏지 않는 선에서 진행.

- 수집: Steam 리뷰 API 등 공식 제공 데이터만 사용 (커뮤니티 무단 크롤링 금지)
- 분류: 긍정, 부정, 중립 비율, 전날 대비 변화, 반응 상위 3개 글
- 비교 실험: LLM 분류 vs HuggingFace 한국어 감정 모델 파인튜닝 (직접 라벨링한 평가 세트로 정확도, 비용 비교)
- 난점: 게임 커뮤니티 반어법, 은어, 밈 ("갓겜이네 ㅋㅋ" 비꼼 등)
- 전송: 슬랙 웹훅, 스케줄은 크론 또는 GitHub Actions

## 하지 않기로 한 것

- 사내 규정 RAG 챗봇 단독 프로젝트 (규칙 문서 기반 설명 기능으로 흡수)
- 넥슨 용어 검수기 재구현 (회사 자산 관련 위험)
- 무조건 자동 커밋하는 봇 (검사 관문 + 사람 확인 방식으로 대체)
